# Той-приглашение — техническое задание (сайт-приглашение)

## 1. Цель проекта

Одностраничный веб-сайт-приглашение на **кыз узатуу + үйлөнүү той** (одно событие,
одно место и время). Сайт заменяет бумажное приглашение: ссылка рассылается
клиентам через WhatsApp/Instagram. Гость открывает ссылку → видит красивый
intro-экран → скроллит вниз через анимированные секции с информацией о тое →
в конце может написать в WhatsApp организатору/паре.

Тон: нежный, лёгкий, "белое золото" (minimal, не аляповато-богатый).
Никакой мобильной "тяжести" — сайт должен плавно работать на среднем
смартфоне через мобильный интернет в Кыргызстане.

## 2. Технологический стек

| Слой | Технология | Комментарий |
|---|---|---|
| Framework | **Next.js 14+ (App Router)** | Один route `/`, статический экспорт возможен |
| Язык | **TypeScript** | |
| Стили | **Tailwind CSS** | + немного кастомного CSS для 3D/шрифтов |
| Анимации скролла | **GSAP + ScrollTrigger** | Основной инструмент анимации |
| Доп. анимации / переходы | **Framer Motion** (опционально) | Для intro-экрана / модалок, если GSAP неудобен там |
| 3D-декор (опционально) | **CSS 3D-transform** в первую очередь; **React Three Fiber / Three.js** только если хочется полноценных 3D-объектов (например, парящие лепестки/кольца) | Не обязательно грузить весь Three.js ради пары декоративных элементов — сначала попробовать CSS |
| Шрифты | **next/font** (Google Fonts, самохостинг) | Playfair Display / Cormorant (serif, заголовки) + Inter или Manrope (sans, тело текста) |
| Хостинг | **Vercel** | `vercel --prod` из корня репозитория |
| Аудио | Обычный HTML5 `<audio>` элемент, файл в `/public/audio/` | Автоплей начинается только после клика на intro-экране (см. раздел про музыку) |
| Иконки | `lucide-react` | Лёгкие, минималистичные иконки (WhatsApp — своя SVG-иконка, т.к. в lucide её нет) |

Пакеты для установки:
```bash
npx create-next-app@latest toy-invite --typescript --tailwind --app
cd toy-invite
npm install gsap framer-motion lucide-react
```

## 4. Дизайн-система (токены)

### 4.1 Цвета
```css
--color-bg:        #FEFCF8;  /* тёплый белый — фон */
--color-cream:     #F5EEE0;  /* кремовый — карточки/секции-подложки */
--color-gold:      #C9A96A;  /* основное золото — акценты, линии, кнопки */
--color-gold-soft: #E4D4B0;  /* светлое золото — hover, второстепенные акценты */
--color-text:      #2C2620;  /* тёмно-коричневый (не чёрный!) — основной текст */
--color-text-muted:#8B7355;  /* приглушённый — подписи, второстепенный текст */
```

Никакого чёрного (#000/#111) и никакого стандартного "AI-серого" —
только эта тёплая палитра.

### 4.2 Типографика
- **Заголовки / имена молодожёнов**: `Cormorant Garamond` или `Playfair Display`
  (serif, лёгкий, элегантный). Имена — главный визуальный акцент сайта,
  крупный кегль (на десктопе ~96–140px для имён на Hero).
- **Основной текст / детали**: `Inter` или `Manrope` (sans-serif, чистый,
  читаемый на маленьких экранах).
- Никаких ALL CAPS-лейблов, никакого "выделения одного слова другим цветом
  в заголовке" — это шаблонные AI-паттерны, которых нужно избегать
  (см. раздел 7).
- Межстрочный интервал у serif-текста чуть больше, чем у sans.

### 4.3 Layout
- Центрированная композиция (это свадебный сайт — симметрия уместна),
  но не обязательно центрировать вообще всё: детали (дата/время/адрес)
  можно выровнять по левому краю внутри карточки для лучшей читаемости.
- Максимальная ширина контента: ~640–720px на десктопе (сайт вертикальный,
  "сторис"-подобный, а не широкий лендинг).
- Много "воздуха" (padding/margin) — минимализм означает пустое
  пространство, а не забитость.

## 5. Структура секций (порядок скролла)

1. **Intro Screen** (см. раздел 6) — оверлей на весь экран, первое, что видит гость.
2. **Hero** — имена пары (кыз узатуу + той — если участвуют разные пары
   имён, показать обе; если одна пара — её имена), дата, короткая
   вступительная фраза. Главный анимационный момент здесь (не путать
   с intro) — можно один раз, при появлении Hero после intro.
3. **Countdown** — обратный отсчёт до даты (дни/часы/минуты). Опционально,
   но хорошо работает эмоционально.
4. **Details** — дата, время, место проведения, кнопка "Открыть на карте"
   (ссылка на 2GIS/Google Maps — placeholder-координаты, клиент заменит).
5. **Gallery** (опционально) — несколько фото пары, placeholder-изображения
   пока нет реальных фото.
6. **WhatsApp CTA** — финальный блок: тёплое пожелание/фраза + кнопка
   "Написать организатору" со ссылкой `https://wa.me/996XXXXXXXXX`
   (номер — placeholder, заменяется на реальный номер клиента).

Каждая секция появляется при скролле через GSAP ScrollTrigger — но
**не** одинаковый "fade-and-slide-up" на каждой секции подряд (это
шаблонный паттерн). Разным секциям — разный характер входа:
например, Hero — имена "собираются" по буквам или разъезжаются от
центра; Details — карточка разворачивается; Gallery — фото выезжают
с небольшим параллаксом при скролле, а не просто фейдят.

## 6. Intro-экран и музыка (важно!)

Браузеры блокируют автовоспроизведение звука без взаимодействия
пользователя. Поэтому:

1. При загрузке сайта показывается полноэкранный **intro-оверлей**
   (золотой/кремовый фон, красивая типографика, что-то вроде
   "Той-беш" / "Нажмите, чтобы открыть приглашение" + декоративный
   элемент — например, стилизованный конверт или орнамент, который
   анимированно "открывается").
2. По клику/тапу:
   - Оверлей плавно скрывается (GSAP timeline: fade + scale + возможно
     "распахивание" в стороны).
   - **В этот же момент** запускается `<audio>.play()` — это
     единственный надёжный момент, когда браузер разрешит звук.
   - Появляется плавающая кнопка mute/unmute (`MusicToggle`) в углу
     экрана — остаётся видимой при скролле (`position: fixed`).
3. Если пользователь до этого промахнулся (например, звук не
   разрешился по какой-то причине) — кнопка mute/unmute всё равно
   должна работать как ручной fallback.

## 7. Анимации — принципы (чтобы не выглядело шаблонно)

- **Один осмысленный анимационный момент** важнее, чем множество мелких
  одинаковых эффектов на каждой карточке. Главные "вау"-моменты:
  открытие intro-экрана и появление Hero с именами.
  Остальные секции — более спокойные, но не одинаковые друг с другом.
- Использовать `ScrollTrigger.batch()` или отдельные таймлайны на
  каждую секцию, а не один универсальный "fade-in-on-scroll" hook,
  копипащенный везде.
- Уважать `prefers-reduced-motion`: если у пользователя эта настройка
  включена — анимации упрощаются/отключаются (GSAP: `gsap.matchMedia()`).
- 3D-элементы — используются точечно как декор (например, парящие
  лепестки/блёстки золота на фоне Hero), а не как основной механизм
  анимации всего сайта. Если ресурсы/время ограничены — приоритет
  у плавных 2D GSAP-анимаций, 3D добавляется последним штрихом.
- Никаких одинаковых hover-эффектов на каждой карточке "по умолчанию" —
  hover нужен только там, где он отвечает на реальное действие
  пользователя (например, кнопка WhatsApp).

## 8. Контент (placeholder на данный момент)

Клиент пришлёт позже:
- Имена пары (для кыз узатуу и/или тоя)
- Точную дату и время
- Адрес места проведения (+ ссылка на карту)
- Номер WhatsApp для кнопки CTA
- Фото пары
- Музыкальный трек (mp3)

До получения контента — использовать понятные placeholder'ы
(например, "Айгерим & Азамат", "00.00.0000", заглушки фото с
нейтральным золотистым фоном), чтобы легко было заменить одним
поиском по файлам.

## 9. Деплой

- Репозиторий пушится на GitHub (или деплоится напрямую).
- Хостинг — **Vercel** (`vercel.com`), фреймворк определится
  автоматически как Next.js.
- Домен: либо стандартный `*.vercel.app`, либо кастомный домен
  позже, если клиент захочет.
- Проверить перед деплоем: работает ли автоплей музыки на iOS Safari
  (там особенно строгие ограничения) — протестировать вручную на
  реальном телефоне после деплоя.

## 10. Чек-лист качества перед сдачей

- [ ] Работает на мобильном (основной сценарий использования)
- [ ] Плавно грузится на среднем 4G-интернете (оптимизировать
      изображения — next/image, сжатие)
- [ ] Кнопка mute/unmute всегда доступна и работает
- [ ] Кнопка WhatsApp открывает правильный номер с преднаписанным
      сообщением (`https://wa.me/996XXXXXXXXX?text=...`)
- [ ] Анимации не дёргаются (тестировать на слабом устройстве, не
      только на мощном ноутбуке разработчика)
- [ ] `prefers-reduced-motion` уважается
- [ ] Видимый keyboard focus на интерактивных элементах (доступность)
- [ ] Проверено на iOS Safari отдельно (автоплей звука там особенный)
